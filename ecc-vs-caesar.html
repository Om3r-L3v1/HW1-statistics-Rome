Two ciphers and how to break them

Part 1 encrypts a message with the Caesar cipher and with modern elliptic-curve encryption on secp256k1, compares the two ciphertexts with the letter statistics of English or Italian, uses those statistics to find the Caesar key, and then tries the same on the ECC ciphertext. Part 2 is Homework (2): the same message is encrypted with a toy elliptic-curve scheme based on the point arithmetic from HMWK 1 and with the Caesar cipher, and both are attacked, Caesar with letter statistics and the toy ECC scheme by searching its small key space.           §2.1Encrypt and decrypt with the toy ECC scheme

          EC-ElGamal is the textbook way to encrypt with an elliptic curve. It only needs the point addition and scalar multiplication from HMWK 1.

          01 · receiverKey generationonce, by the receiver

          The receiver keeps the private key k and publishes the public key Q = kG, so anyone can encrypt messages for them. Getting k back from Q is the elliptic-curve discrete logarithm problem from HMWK 1.

          02 · senderEncodepublic rule, no key

          03 · senderEncryptuses Q and a fresh random r

          For each block the sender picks a random r and sends C1 = r·G and C2 = M + r·Q. The point r·Q works as a one-time mask, and C1 is what allows the key owner to rebuild it.

          §2.2The Caesar cipher

          Every letter is shifted by the same amount s. We use the same message as in §2.1 and leave the spaces unchanged.

          encryptE(x) = (x + s) mod 26
          decryptD(y) = (y − s) mod 26

          The same key s is used to encrypt and to decrypt (a symmetric cipher), and a plaintext letter always becomes the same ciphertext letter. In the table above each highlighted column is used for every occurrence of that letter.

          §2.3Similarities and differences

          How the procedures, the key spaces and the ciphertext statistics compare.

          What they have in common. Both schemes encrypt by adding a secret shift in a group. Caesar adds s in the group of 26 letters, and EC-ElGamal adds the point r·Q in the group of curve points. The difference is where the shift comes from. Caesar uses one fixed shift for all letters, agreed in advance. EC-ElGamal uses a new random shift for each block, agreed through Diffie–Hellman, and only the private key can remove it.

            §2.4Statistical cryptanalysis of the Caesar cipher

            First we estimate how English letters are distributed from a corpus, then we choose the shift whose decryption looks most like English.

            Corpus letter frequencies

            The algorithm

            1. Model the language. Count the probability p(x) of each letter and p(y | x) of each letter pair in the training corpus.
            2. Try every key. Decrypt the ciphertext with all 26 shifts. This part is easy; the real problem is recognising the correct plaintext.
            3. Score each candidate. We use the χ² distance between its letter counts and the corpus frequencies (lower is better), the log-likelihood of its letter pairs under the bigram model (higher is better), or the share of its words that appear in the corpus vocabulary.
            4. Pick the best score. For comparison we also include the shortcut "most frequent ciphertext letter = E", which needs no search at all.
            Use your own training corpus (paste text or load a .txt file)

            The built-in corpus has about 2,500 words of plain English prose, and its last four paragraphs are kept apart for testing. A larger English text (for example a public-domain book saved as .txt) gives a better model. For your own corpus, 80% is used for training and 20% for testing.

              Effectiveness and limitations

              Why it works. Caesar is deterministic and works letter by letter. Every plaintext E becomes the same ciphertext letter, so the shape of the English letter distribution survives the encryption and is only shifted. With a few dozen letters, matching this shape finds the key almost every time.

              When it fails. With only a few letters the counts are mostly noise. A 6-letter word does not have to contain an E, and several shifts can give plausible fragments. Text that is not ordinary prose (names, abbreviations, numbers, another language, or text written to avoid common letters) breaks the assumption behind the model. The method also has to know the language, since an English model scores French text badly.

              The key space is not the problem. There are only 26 keys, so all of them can be tried, and the statistics are only needed to recognise the right one. The same scoring also breaks ciphers with much larger key spaces, such as a general substitution cipher (26! ≈ 288 keys), using a search that moves towards better n-gram scores instead of trying every key.

              §2.5Attacking the toy ECC scheme

              The weak point is the small key space, not the curve arithmetic. The attacker knows the public parameters, the public key Q and the ciphertext from §2.1.

              
      
              
        
              The attack
              
        
              Exhaustive search. Start with R = G and keep adding G, so R = 1·G, 2·G, 3·G, …, and compare each R with the public key Q. The first match gives k, and with k every block can be decrypted just as the receiver does. Each candidate costs one point addition, so at most |key range| additions are needed.
              
        
              Baby-step giant-step. Write k = i·m + j with m ≈ √K. First store the m "baby" points j·G in a table, then take "giant" steps Q − i·(m·G) until one of them is in the table. This takes about 2√K additions instead of K, but needs memory for √K points. The same square-root speed-up is behind all generic discrete-log attacks.
              
        
              Without k. On the toy curves the random values r are small too, so each r can be found from C1 = r·G with the same search and the block decrypted as C2 − r·Q. On the secp256k1 options only k is restricted and r is a full 256-bit number, so this does not work there.

              Why this does not work against real ECC
              
        
              
        
              Exhaustive search is not the best attack on a full-size key, but the best known attack is not much better. For a well-chosen curve such as secp256k1 (prime order, no special structure) the fastest known method is Pollard's rho, which needs about √n ≈ 2128 group operations and very little memory. Baby-step giant-step needs the same time plus 2128 stored points. All generic algorithms have the same square-root limit, so a 256-bit key gives about 128 bits of security, and the encryption does not leak any statistics that could be used as a shortcut.

              Pollard's kangaroo (λ)Restricted key spaceDesigned for a key known to lie in an interval [a, b]: √(b − a) steps like BSGS, but almost no memory.
              
            
              Precomputed tables, any rToy curve designOn the mod-17 and mod-97 curves the whole group has 18 or 79 points, so every discrete log (k and every r) can be looked up. "Recover each r" above uses this.
              
            
              Small subgroupsToy curve designMod 17 the group has 18 = 2·3² points and G generates only 9 of them. With k = 6 (a multiple of 3) the mask r·Q can only be O, 3G or 6G, so every block with r = 3 or 6, a quarter of them, is sent unmasked (§2.1, §2.3). Implementations that accept points without checking them can also be fed low-order points that leak k modulo small numbers. secp256k1 has prime order and cofactor 1.
              
            
              Anomalous or weak curvesToy curve designCurves with exactly p points (mod 61 and mod 127 in HMWK 1) have a polynomial-time discrete-log attack (Smart's attack). Curve choice matters, not just size.
              
            
              Reused or predictable rScheme design ImplementationWith one r for all blocks, C2 differences reveal plaintext differences and the scheme collapses into a Caesar cipher. Demonstrated below.
              
            
              MalleabilityScheme designThere is no authentication: adding G to C2 turns every symbol into the next one, without the key. Demonstrated below. Real schemes (ECIES) add a MAC.
              
            
              Reordering, deleting blocksScheme designEach symbol is encrypted on its own, so blocks can be dropped, repeated or reordered unnoticed, and the ciphertext length gives away the message length.
              
            
              Weak key generationRestricted key space ImplementationA real example of the same problem: keys generated from too little randomness. The "Profanity" vanity-address tool seeded keys with only 32 random bits, and in 2022 attackers recovered such Ethereum keys and emptied the wallets.
              
            
              Side channelsImplementationA naive double-and-add takes longer for 1-bits than for 0-bits, so timing or power traces can reveal k. Production code uses constant-time arithmetic.
