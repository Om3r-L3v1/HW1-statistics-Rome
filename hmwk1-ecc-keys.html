Private key → public key

Ethereum turns a private key into a public key with elliptic-curve scalar multiplication on secp256k1. Part 1 does the same on a toy version of that curve, small enough to see every point: pick a private key k, and the page adds the base point G to itself until it reaches Q = kG, animating each addition. Part 2 repeats the experiment for many keys and asks whether the outputs look random.

            DiscussionWhat the statistics can and cannot say
            
    
            
      
            
        
            Statistics can show that a function is not random-looking. They can never show that it is one-way. One-wayness is a claim about computational cost, and on these toy curves every key can be recovered by trying all n − 1 of them in a few milliseconds, however random the outputs look.
            

        
            Properties that matter for a one-way function
            
        
            Easy forward, infeasible backward. Double-and-add computes kG in about log₂ k steps. Going back is the elliptic-curve discrete logarithm problem. Its difficulty depends on the size of the group (secp256k1: n ≈ 2256, so about 2128 steps with Pollard's rho) and on avoiding special curves. None of the tests above measures that.
            
        
            A one-to-one map onto a large prime-order group. k ↦ kG is a bijection from {1, …, n − 1} onto the points other than O (Test D: no two keys share a public key). A uniformly random private key therefore gives a uniformly random point of the group, which is what key generation needs. A prime order with cofactor 1, as in secp256k1 and in every prime offered above except 17, rules out small subgroups. On the assignment curve mod 17 the group has 18 points, and G = (1, 5) generates only 9 of them.
            
        
            Structure is allowed, and needed. (a + b)G = aG + bG holds every time (Test D). Diffie–Hellman key exchange and ECDSA signatures, including Ethereum's transaction signatures, rely on exactly this. The mirror symmetry kG ↔ −kG and the repeated x-values (Test B) are part of the same structure. The primes 61 and 127 are left out of the menu for a related reason: there the curve has exactly p points, an "anomalous" curve on which the discrete logarithm is easy.
            

        
            Properties that belong to hash functions
            
        
            Uniform values, balanced bits, avalanche, no relations. A hash should behave like a random function: every output value about equally likely, every bit 1 half the time, each input-bit flip changing each output bit with probability ½, and no computable relation between H(a), H(b) and H(a + b). Collisions must exist, since a hash compresses arbitrary-length input, but must be infeasible to find.
            
        
            The toy curve fails the "no relations" test completely. Anyone holding Q = kG can compute (k + 1)G = Q + G or 2kG without knowing k, and x(kG) = x((n − k)G) for every k. The value counts in Test B are also far too regular: each x that appears does so exactly twice. On the summary numbers (correlation near 0, χ² near 1, bit shares near the range limit, average avalanche close to the baseline) the curve and SHA-256 look alike. Those tests are necessary for a hash but weak: they miss structure that is algebraic rather than bit-level.
            
        
            The top-bit bias is not about the curve. Both functions show it, because both output a number below p, and p is not a power of two. For secp256k1, p is within 233 of 2256, so the same bias is about 2−224 and cannot be measured.
            

        
            Why Ethereum uses both
            
        
            Ethereum needs the algebra of scalar multiplication for keys and signatures, and the randomness of a hash for addresses. So it computes Q = kG on secp256k1, then hashes the 64-byte public key with Keccak-256 and keeps the last 20 bytes as the address. The structured curve point never serves as an identifier directly; the hash removes the structure measured on this sheet.
